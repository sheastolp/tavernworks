Local AI

My own AI chat, running on a gaming laptop in the back room. No cloud, no data centre, no subscription.

RUNNING SELF-HOSTED GTX 1650
💬 Chat in the browser

Works from any device, nothing to install. The chat always talks to the FX705, so it only answers while the laptop is awake.

THE IDEA

Most AI chat is a thin window onto someone else's server. Every message goes off to a data centre and gets logged somewhere you can't see.

This one lives at home. An ASUS TUF Gaming FX705DT runs headless Ubuntu 26.04 with the lid shut, serving a large language model on its GeForce GTX 1650. The chats stay on hardware I own.

THE RIG
💻

ASUS TUF FX705DT

A 17" gaming laptop with a Ryzen CPU and a GeForce GTX 1650 (4 GB), put to work as a server. Headless Ubuntu 26.04 LTS, no monitor, no desktop.

🦙

Ollama

Downloads and runs the models on the GTX 1650 through CUDA, spilling over to the CPU when a model doesn't fit in 4 GB. Listens on port 11434 and powers both chat pages. Runs as a systemd service.

💬

Open WebUI

A ChatGPT-style chat page sitting on top of Ollama, with DuckDuckGo web search, on port 8080. Installed with uv in its own Python 3.11 environment and run as a systemd service.

🔗

Tailscale

A private network between my own devices. I SSH in over it, and Tailscale Funnel puts the gate on the internet so the browser chat works from anywhere, without visitors needing Tailscale.

🌐

Web search

A tiny no-dependency Node server that searches DuckDuckGo and reads pages, so the browser chat's models (and GuildScribe's !askme) can look things up. No API key.

✳️

Claude Code bridge

Optional and rarely used: puts Claude Code in the browser chat's model list, running in a work folder on the laptop as its own user.

The browser chat on this site reaches the laptop through the gate, on Tailscale Funnel port 10000. The gate only lets chats, model lists and web searches through, never the rest of Ollama. Ollama itself, Open WebUI (port 8080) and the Claude Code bridge stay on the tailnet.

CHAT FROM THE BROWSER

The browser chat is a lightweight, Open WebUI-style client that only talks to the FX705. The page loads from this site, then your browser talks to the laptop's gate directly; chats are kept in your own browser. There's nothing to set up on the visitor's side: no addresses, no Tailscale.

  1. Run the web search server

    So models can look things up on DuckDuckGo and read pages, no API key needed. It runs as a systemd service from /opt/local-ai-search; setup in its README. The gate passes searches to it on the laptop, so it needs no address of its own.

  2. Run the gate

    A small no-dependency Node server that lets the chat through to Ollama and web search, and nothing else: no pulling or deleting models, capped sizes, rate limits per visitor. Setup in its README.

  3. Put the gate on the funnel

    sudo tailscale funnel --bg --https=10000 http://127.0.0.1:8793
tailscale funnel status

    Check from any device, even one off the tailnet: https://sheamus-tuf-gaming-fx705dt-fx705dt.tail2c8da4.ts.net:10000/health should say "ollama":true. The chat has this address built in.

  4. Optional: Claude Code, for me only

    The Claude Code bridge adds Claude Code to the chat's model list. It runs Claude Code on my Claude account as its own claude-bridge user, in a work folder on the laptop, and only answers requests carrying its token. It can run commands, so it stays on the tailnet and never goes through the gate. Setup in its README; then paste the token into the chat's ⚙ Settings on a device that's on the tailnet:

    sudo tailscale serve --bg --https=8445 http://127.0.0.1:8792
WHEN THE CHAT CAN'T CONNECT
"Can't reach the laptop"

Nothing answered at the gate. Check in this order: the laptop is awake; the gate is running (systemctl status local-ai-gate); tailscale funnel status still lists port 10000; and the device's browser VPN is off (some, like Opera GX's, block unusual ports).

"The laptop's gate doesn't allow this website"

The page was opened from somewhere other than tavernworks.dev. Add that address to GATE_ORIGINS in the gate's service file if it should be allowed.

"You're going fast" or "the laptop is busy"

The gate's limits: 60 replies per visitor per 10 minutes, 400 for everyone, and at most 4 replies waiting for the GPU. Wait a little and resend.

Web search is on, but the model never searches

The reply says why underneath. "Can't use tools": pick a model that can, like llama3.2. A search marked failed: Test connection in ⚙ Settings shows whether the search server is up, and journalctl -u local-ai-search on the laptop shows what went wrong. Small models also sometimes just answer from memory; asking them to "search for" something helps.

Connected, but no models in the list

Ollama has nothing downloaded yet. On the laptop: ollama pull llama3.2 (models up to about 4B fit the GPU's 4 GB best), then reload the chat.

LIFE ON A 4 GB GPU
⚡

Quicker replies

With the model on the graphics card, text streams out several times faster than it did on the old CPU-only laptop.

⚖️

Mid-size models

Quantized models up to about 4B fit entirely in the 4 GB of VRAM: llama3.2 (2 GB) is the everyday one. Bigger ones still run, split between GPU and CPU, just slower: qwen3.5-abliterated is 17 GB, so most of it runs on the CPU.

FORGE YOUR OWN

Got an old laptop or gaming rig gathering dust? The basic recipe on Ubuntu is short. Check each project's docs for the current install steps.

1. Install the NVIDIA driver

sudo ubuntu-drivers install
sudo reboot
nvidia-smi   # should list the GPU

2. Install Ollama and pull a small model

curl -fsSL https://ollama.com/install.sh | sh
ollama run llama3.2

3. Put Open WebUI in front of it

Open WebUI wants Python 3.11, which newer Ubuntu doesn't ship. uv fetches it and makes a separate environment for it:

curl -LsSf https://astral.sh/uv/install.sh | sh
uv venv --python 3.11 /opt/open-webui/venv
uv pip install --python /opt/open-webui/venv/bin/python open-webui

Then run it as a service, in /etc/systemd/system/open-webui.service:

[Unit]
Description=Open WebUI
After=network-online.target ollama.service
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/open-webui
Environment=DATA_DIR=/opt/open-webui/data
Environment=OLLAMA_BASE_URL=http://127.0.0.1:11434
Environment=PORT=8080
ExecStart=/opt/open-webui/venv/bin/open-webui serve
Restart=always

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now open-webui

Updating later: uv pip install --python /opt/open-webui/venv/bin/python -U open-webui, then sudo systemctl restart open-webui.

4. Join it to your Tailscale network

curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up

Then open http://<machine-name>:8080 from any device on your tailnet, or SSH in to manage it. The first account you make is the admin. No ports opened to the internet.

QUESTIONS AT THE BAR
Can I use it?

It's a personal setup on my own private network, not a public service. The recipe above will get you your own.

Is it as good as ChatGPT?

No. Small models running on a laptop GPU can't match the big hosted ones. They're still handy for everyday questions, drafting and tinkering, and they're private.

Why a laptop?

It was already there. Laptops are quiet, sip power and come with a built-in battery backup, which makes them decent little home servers.

What changed from the old laptop?

Local AI started on a retired Lenovo Yoga 730 with no graphics card Ollama could use, so the CPU did everything. The ASUS TUF has an NVIDIA GTX 1650, which Ollama uses automatically once the NVIDIA driver is installed (sudo ubuntu-drivers install, then reboot). ollama ps shows how much of a loaded model sits on the GPU.
