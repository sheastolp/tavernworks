Local AI

My own AI chat, running on a gaming laptop in the back room. No cloud, no data centre, no subscription.

RUNNING SELF-HOSTED GTX 1650
💬 Chat in the browser ↗ Open Local AI ↗ Open Tailscale

The chat and Open Local AI only work from my own devices: the tailnet, or the laptop's home network.

THE IDEA

Most AI chat is a thin window onto someone else's server. Every message goes off to a data centre and gets logged somewhere you can't see.

This one lives at home. An ASUS TUF Gaming FX705DT runs headless Ubuntu 26.04 with the lid shut, serving a large language model on its GeForce GTX 1650. The chats stay on hardware I own.

THE RIG
💻

ASUS TUF FX705DT

A 17" gaming laptop with a Ryzen CPU and a GeForce GTX 1650 (4 GB), put to work as a server. Headless Ubuntu 26.04 LTS, no monitor, no desktop.

🦙

Ollama

Downloads and runs the models on the GTX 1650 through CUDA, spilling over to the CPU when a model doesn't fit in 4 GB. Listens on port 11434 and powers both chat pages. Runs as a systemd service.

💬

Open WebUI

A ChatGPT-style chat page sitting on top of Ollama, with DuckDuckGo web search, on port 8080. Installed with uv in its own Python 3.11 environment and run as a systemd service.

🔗

Tailscale

A private network between my own devices. I SSH in over it, and tailscale serve gives Ollama, the web search server and the Claude Code bridge HTTPS addresses for the browser chat.

🌐

Web search

A tiny no-dependency Node server that searches DuckDuckGo and reads pages, so the browser chat's models (and GuildScribe's !askme) can look things up. No API key.

✳️

Claude Code bridge

Optional and rarely used: puts Claude Code in the browser chat's model list, running in a work folder on the laptop as its own user.

CHAT FROM THE BROWSER

The browser chat is a lightweight, Open WebUI-style client that talks straight to Ollama over Tailscale. Nothing passes through this website: the page loads here, then your browser talks to the laptop directly. It only works from devices on the tailnet, and the laptop's addresses are saved in your own browser, never on this site.

  1. Give Ollama an HTTPS address on the tailnet

    This site is HTTPS, so browsers won't let it call plain http://. In the Tailscale admin console, under DNS, turn on MagicDNS and Enable HTTPS. Then, on the laptop:

    sudo tailscale serve --bg 11434

    It prints the address, something like https://<machine>.<tailnet>.ts.net/, and keeps serving across reboots. Lost it? tailscale serve status shows it again, or find the machine's full domain name in the admin console's Machines list.

  2. Let tavernworks.dev talk to Ollama

    sudo systemctl edit ollama
# in the editable area at the top, add:
[Service]
Environment="OLLAMA_ORIGINS=https://tavernworks.dev"

sudo systemctl restart ollama
systemctl show ollama --property=Environment   # should list it

    This laptop also sets OLLAMA_HOST to 0.0.0.0:11434 there, so Ollama answers on the home network too. The browser chat doesn't need that.

  3. Check it, then connect

    From a device on the tailnet, open the address from step 1 in a tab. It should say "Ollama is running". Then open the chat, paste it into ⚙ Connection settings, add Open WebUI's address (the laptop's tailnet name, port 8080) so Open Local AI goes straight there, hit Test connection, then Save.

  4. Optional: let it search the web

    A small search server on the laptop lets models look things up on DuckDuckGo and read pages, no API key needed. It runs as a systemd service from /opt/local-ai-search (setup in its README), with its own HTTPS address. Paste that into Search server address in the chat's settings:

    sudo tailscale serve --bg --https=8444 http://127.0.0.1:8791

    🌐 next to 📎 turns search on and off, and it starts on. It needs a model that can use tools, like llama3.2.

  5. Optional: Claude Code

    The Claude Code bridge adds Claude Code to the chat's model list. It runs Claude Code on my Claude account as its own claude-bridge user, in a work folder on the laptop, and only answers requests carrying its token. Setup in its README; its address goes in Bridge address:

    sudo tailscale serve --bg --https=8445 http://127.0.0.1:8792
WHEN THE CHAT CAN'T CONNECT
"Can't reach the laptop"

Nothing answered at the Ollama address. Check in this order: the device is connected to Tailscale; the browser's own VPN is off (Opera GX's built-in VPN, for one, sends traffic through Opera's servers, which can't see the tailnet); the laptop is awake; and tailscale serve status on the laptop still lists the address. If it doesn't, run sudo tailscale serve --bg 11434 again.

"The laptop answered, but Ollama isn't letting this site in"

The address works but OLLAMA_ORIGINS isn't set, or Ollama wasn't restarted after setting it. Do step 2 above and check with systemctl show ollama --property=Environment.

The Ollama address won't open in a tab

HTTPS certificates may be off: Tailscale admin console → DNS → Enable HTTPS. The first visit after that can take 10–20 seconds while the certificate is issued.

The browser asks about devices on my local network

Allow it. Some browsers ask before a website may talk to devices on private networks, and the tailnet counts as one.

Open WebUI works but the browser chat doesn't

They take different routes: Open WebUI is reached directly on port 8080, while the browser chat needs the HTTPS address from tailscale serve plus the OLLAMA_ORIGINS setting. Steps 1 and 2 above cover both.

Web search is on, but the model never searches

The reply says why underneath. "No search server is set up": add its address in ⚙ Connection settings. "Can't use tools": pick a model that can, like llama3.2. A search marked failed: Test connection shows whether the search server is reachable, and journalctl -u local-ai-search on the laptop shows what went wrong. Small models also sometimes just answer from memory; asking them to "search for" something helps.

Connected, but no models in the list

Ollama has nothing downloaded yet. On the laptop: ollama pull llama3.2 (models up to about 4B fit the GPU's 4 GB best), then reload the chat.

LIFE ON A 4 GB GPU

FORGE YOUR OWN

Got an old laptop or gaming rig gathering dust? The basic recipe on Ubuntu is short. Check each project's docs for the current install steps.

1. Install the NVIDIA driver

sudo ubuntu-drivers install
sudo reboot
nvidia-smi   # should list the GPU

2. Install Ollama and pull a small model

curl -fsSL https://ollama.com/install.sh | sh
ollama run llama3.2

3. Put Open WebUI in front of it

Open WebUI wants Python 3.11, which newer Ubuntu doesn't ship. uv fetches it and makes a separate environment for it:

curl -LsSf https://astral.sh/uv/install.sh | sh
uv venv --python 3.11 /opt/open-webui/venv
uv pip install --python /opt/open-webui/venv/bin/python open-webui

Then run it as a service, in /etc/systemd/system/open-webui.service:

[Unit]
Description=Open WebUI
After=network-online.target ollama.service
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/open-webui
Environment=DATA_DIR=/opt/open-webui/data
Environment=OLLAMA_BASE_URL=http://127.0.0.1:11434
Environment=PORT=8080
ExecStart=/opt/open-webui/venv/bin/open-webui serve
Restart=always

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now open-webui

Updating later: uv pip install --python /opt/open-webui/venv/bin/python -U open-webui, then sudo systemctl restart open-webui.

4. Join it to your Tailscale network

curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up

Then open http://<machine-name>:8080 from any device on your tailnet, or SSH in to manage it. The first account you make is the admin. No ports opened to the internet.

QUESTIONS AT THE BAR
Can I use it?

It's a personal setup on my own private network, not a public service. The recipe above will get you your own.

Is it as good as ChatGPT?

No. Small models running on a laptop GPU can't match the big hosted ones. They're still handy for everyday questions, drafting and tinkering, and they're private.

Why a laptop?

It was already there. Laptops are quiet, sip power and come with a built-in battery backup, which makes them decent little home servers.

What changed from the old laptop?

Local AI started on a retired Lenovo Yoga 730 with no graphics card Ollama could use, so the CPU did everything. The ASUS TUF has an NVIDIA GTX 1650, which Ollama uses automatically once the NVIDIA driver is installed (sudo ubuntu-drivers install, then reboot). ollama ps shows how much of a loaded model sits on the GPU.
