RUNNING SELF-HOSTED GTX 1650
💬 Chat in the browser

Works from any device, nothing to install. The chat always talks to the FX705, so it only answers while the laptop is awake.

THE IDEA

Most AI chat is a thin window onto someone else's server. Every message goes off to a data centre and gets logged somewhere you can't see.

This one lives at home. An ASUS TUF Gaming FX705DT runs headless Ubuntu 26.04 with the lid shut, serving a large language model on its GeForce GTX 1650. The chats stay on hardware I own.

THE RIG
💻

ASUS TUF FX705DT

A 17" gaming laptop with a Ryzen CPU and a GeForce GTX 1650 (4 GB), put to work as a server. Headless Ubuntu 26.04 LTS, no monitor, no desktop.

🦙

Ollama

Downloads and runs the models on the GTX 1650 through CUDA, spilling over to the CPU when a model doesn't fit in 4 GB. Listens on port 11434 and powers both chat pages. Runs as a systemd service.

💬

Open WebUI

A ChatGPT-style chat page sitting on top of Ollama, with DuckDuckGo web search, on port 8080. Installed with uv in its own Python 3.11 environment and run as a systemd service.

🔗

Tailscale

A private network between my own devices. I SSH in over it, and Tailscale Funnel puts the gate on the internet so the browser chat works from anywhere, without visitors needing Tailscale.

🌐

Web search

A tiny no-dependency Node server that searches DuckDuckGo and reads pages, so the browser chat's models (and GuildScribe's !askme) can look things up. No API key.

✳️

Claude Code bridge

Optional and rarely used: puts Claude Code in the browser chat's model list, running in a work folder on the laptop as its own user.

CHAT FROM THE BROWSER

The browser chat is a lightweight, Open WebUI-style client that only talks to the FX705. The page loads from this site, then your browser talks to the laptop's gate directly; chats are kept in your own browser. It's locked to my own devices with the laptop key; no addresses or Tailscale needed on them. Replies keep going on the laptop if a phone locks or a tab goes to sleep, and the page picks them back up.

  1. Run the web search server

    So models can look things up on DuckDuckGo and read pages, no API key needed. It runs as a systemd service from /opt/local-ai-search; setup in its README. The gate passes searches to it on the laptop, so it needs no address of its own.

  2. Run the gate

    A small no-dependency Node server that lets the chat through to Ollama and web search, and nothing else: no pulling or deleting models, capped sizes, rate limits per visitor. Setup in its README.

  3. Put the gate on the funnel

    sudo tailscale funnel --bg --https=10000 http://127.0.0.1:8793
tailscale funnel status

  4. Make the laptop key and put it on your devices

    sudo install -d -m 700 /etc/local-ai-gate
openssl rand -base64 18 | tr '+/' '-_' | sudo tee /etc/local-ai-gate/key >/dev/null
sudo chmod 600 /etc/local-ai-gate/key
sudo mkdir -p /etc/systemd/system/local-ai-gate.service.d
printf '[Service]\nLoadCredential=gate-key:/etc/local-ai-gate/key\n' | sudo tee /etc/systemd/system/local-ai-gate.service.d/key.conf
sudo systemctl daemon-reload && sudo systemctl restart local-ai-gate

    Then sudo cat /etc/local-ai-gate/key and paste it into the chat's ⚙ Settings → Laptop key (or Rosin's ⋯ → Laptop key). For a phone, use ⚙ Settings → Show QR code with "Include the laptop key" ticked on a device that has it. More ways in the gate's README.

    Check from any device, even one off the tailnet: https://sheamus-tuf-gaming-fx705dt-fx705dt.tail2c8da4.ts.net:10000/health should say "ollama":true. The chat has this address built in.

  5. Optional: natural voices for Rosin

    Rosin can talk with Kokoro, a free neural voice that runs on the laptop's CPU, instead of the device's built-in voice. It runs inside speaches (the same server as Rosin's Whisper), and the gate passes it through with the laptop key. Run these one at a time as root. First, see whether speaches is already running:

    curl -s http://127.0.0.1:8000/health

    If nothing answers, start it:

    docker run --detach --restart unless-stopped --publish 127.0.0.1:8000:8000 --name speaches --volume hf-hub-cache:/home/ubuntu/.cache/huggingface/hub ghcr.io/speaches-ai/speaches:latest-cpu

    Download the Kokoro voice model into it (about 350 MB):

    curl -X POST "http://127.0.0.1:8000/v1/models/speaches-ai/Kokoro-82M-v1.0-ONNX"

    Check it can talk (it should print a file size, not 0):

    curl -s -X POST http://127.0.0.1:8000/v1/audio/speech -H "content-type: application/json" -d '{"model":"speaches-ai/Kokoro-82M-v1.0-ONNX","voice":"am_michael","input":"Hey, it is Rosin."}' -o /tmp/rosin.mp3 && ls -l /tmp/rosin.mp3

    Update the gate so it passes voices through, then restart it:

    curl -fsSL https://tavernworks.dev/local-ai/gate/server.mjs -o /opt/local-ai-gate/server.mjs
    systemctl restart local-ai-gate
    curl -s http://127.0.0.1:8793/health

    That last one should say "voices":true. Then in Rosin, open ⋯ → Rosin's voice and pick one under Natural voices from the laptop. Each device keeps its own pick, speed and pitch.

  6. Optional: let Rosin see photos

    Tap 📷 by Rosin's chat box to take or pick a photo (or paste one), then say or type something, or just tap Send. The AI Pool's Qwen3.5 35B-A3B can see, but only with its vision file (an "mmproj", about 610 MB), which llama-server loads beside the model. It stays in the laptop's RAM, so the model keeps its share of the 4 GB card. One at a time as root:

    curl -fL -o /root/ai-pool/Huihui-Qwen3.5-35B-A3B-abliterated.mmproj-Q8_0.gguf https://huggingface.co/mradermacher/Huihui-Qwen3.5-35B-A3B-abliterated-GGUF/resolve/main/Huihui-Qwen3.5-35B-A3B-abliterated.mmproj-Q8_0.gguf
    curl -fsSL https://tavernworks.dev/local-ai/gate/pool-eyes.sh -o /opt/ai-pool/pool-eyes.sh
    chmod +x /opt/ai-pool/pool-eyes.sh
    mkdir -p /etc/systemd/system/ai-pool-solo.service.d
    printf '[Service]\nExecStart=\nExecStart=/opt/ai-pool/pool-eyes.sh\n' > /etc/systemd/system/ai-pool-solo.service.d/eyes.conf
    curl -fsSL https://tavernworks.dev/local-ai/gate/server.mjs -o /opt/local-ai-gate/server.mjs
    systemctl daemon-reload
    systemctl restart ai-pool-solo
    systemctl restart local-ai-gate
    journalctl -u ai-pool-solo -n 60 --no-pager | grep -iE "eyes|mmproj|vision"
    curl -s http://127.0.0.1:8793/health

    The journal line should say Eyes: …mmproj-Q8_0.gguf, and once the model has loaded (a minute or two) the last one should say "poolVision":true. pool-eyes.sh runs your usual fx705-solo.sh unchanged; it only adds the vision file when one in /root/ai-pool is named like the model, so switching to another model just starts it without eyes. Photos are shrunk to 896 px before they're sent, and the laptop takes some extra seconds on each one. To turn eyes off, delete the mmproj file and restart ai-pool-solo.

  7. Optional: let Rosin change its own app and your other repos

    Ask Rosin for a change ("make the Talk button bigger", "in GuildScribe, add a help command") or type one under ⋯ → Changes, where Where picks the repo or lets Rosin work it out from your words (Rosin's own app when you name nothing else). The laptop's model drafts it as a pull request on GitHub, and it waits there until you tap Approve in Rosin. Undo puts it back. It never touches workflows, hidden files like .env, secrets, keys, settings or build config files, or this gate. The GitHub token reaches only the repos you give it, and it stays on the laptop.

    First make the token on GitHub: your picture → Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token. Name it "Rosin self-updates", pick an expiry, set Repository access to Only select repositories and tick each repo Rosin may change (tavernworks first), and under Repository permissions set Contents and Pull requests to Read and write. Generate it and copy it. Then on the laptop, one at a time as root. This one waits for you to paste the token and press Enter, without showing it:

    read -rs -p "Paste the GitHub token: " T && printf '%s' "$T" | sed 's/\x1b\[[0-9]*~//g' | grep -oE '(github_pat|gh[pousr])_[A-Za-z0-9_]+' > /etc/local-ai-gate/github-token && unset T && echo saved
    chmod 600 /etc/local-ai-gate/github-token
    printf '[Service]\nLoadCredential=github-token:/etc/local-ai-gate/github-token\n' > /etc/systemd/system/local-ai-gate.service.d/github.conf
    curl -fsSL https://tavernworks.dev/local-ai/gate/server.mjs -o /opt/local-ai-gate/server.mjs
    systemctl daemon-reload
    systemctl restart local-ai-gate
    curl -s http://127.0.0.1:8793/health

    That last one should say "selfUpdate":true and "githubToken":"ok". The gate reads the token only when it starts, so after changing the token file, restart the gate. Drafting uses the AI Pool's model when it's up (or an Ollama model) and takes a few minutes; Rosin tells you when one is ready. The first reply after a draft is slower, because the model has to read Rosin's prompt again. To stop it, delete the token on GitHub or remove github.conf and restart the gate.

  8. Optional: let Rosin use your Gmail, Calendar and Drive

    Rosin can search and read your email, tell you what needs you, write replies, check your calendar and read Docs from Drive. Anything that sends or changes something (sending, saving a draft, archiving, trash, labels, marking read, adding an event) shows a card with exactly who it goes to and every word, and happens only when you tap it. It's off in OBS, while Twitch chat is on, and for anyone who isn't you. The Google sign-in stays on the laptop.

    First make your own Google sign-in app at console.cloud.google.com: create a project called Rosin; under APIs & Services → Library turn on Gmail API, Google Calendar API and Google Drive API; under Google Auth Platform → Branding name it Rosin with your email, pick External, then under Audience tap Publish app (in Testing, Google signs it out every 7 days); under Clients create a Desktop app client and keep its Client ID and Client secret handy. Then on the laptop, one at a time as root:

    curl -fsSL https://tavernworks.dev/local-ai/gate/server.mjs -o /opt/local-ai-gate/server.mjs
    node /opt/local-ai-gate/server.mjs google-setup

    It asks for the Client ID and secret (paste each and press Enter), then which parts (just press Enter for all three), and prints a link. Open the link on your phone, pick your account, tap Advanced → Go to Rosin past the "hasn't verified this app" warning (it's your own app), and allow it. Google then opens a page at 127.0.0.1 that won't load: copy that whole address and paste it into the laptop. It saves the sign-in in /etc/local-ai-gate/google.json and restarts the gate. To check:

    curl -s http://127.0.0.1:8793/health

    That should say "google":true. In Rosin, ⋯ → Rosin can use my Google shows the account, and ✉️ Mail asks what in your email needs you. Rosin treats what emails say as information and never as instructions. It can't delete mail for good (trash only) or change Drive. To stop it, untick the setting, or remove Rosin under myaccount.google.com → Security → Your connections to third-party apps.

  9. Optional: Claude Code, for me only

    The Claude Code bridge adds Claude Code to the chat's model list. It runs Claude Code on my Claude account as its own claude-bridge user, in a work folder on the laptop, and only answers requests carrying its token. It can run commands, so it stays on the tailnet and never goes through the gate. Setup in its README; then paste the token into the chat's ⚙ Settings on a device that's on the tailnet:

    sudo tailscale serve --bg --https=8445 http://127.0.0.1:8792
WHEN THE CHAT CAN'T CONNECT
"Can't reach the laptop"

Nothing answered at the gate. Check in this order: the laptop is awake; the gate is running (systemctl status local-ai-gate); tailscale funnel status still lists port 10000; and the device's browser VPN is off (some, like Opera GX's, block unusual ports).

"The laptop's gate doesn't allow this website"

The page was opened from somewhere other than tavernworks.dev. Add that address to GATE_ORIGINS in the gate's service file if it should be allowed.

"You're going fast" or "the laptop is busy"

The gate's limits: 60 replies per visitor per 10 minutes, 400 for everyone, and at most 4 replies waiting for the GPU. Wait a little and resend.

Web search is on, but the model never searches

The reply says why underneath. "Can't use tools": pick a model that can, like llama3.2. A search marked failed: Test connection in ⚙ Settings shows whether the search server is up, and journalctl -u local-ai-search on the laptop shows what went wrong. Small models also sometimes just answer from memory; asking them to "search for" something helps.

Connected, but no models in the list

Ollama has nothing downloaded yet. On the laptop: ollama pull llama3.2 (models up to about 4B fit the GPU's 4 GB best), then reload the chat.

LIFE ON A 4 GB GPU
⚡

Quicker replies

With the model on the graphics card, text streams out several times faster than it did on the old CPU-only laptop.

⚖️

Mid-size models

Quantized models up to about 4B fit entirely in the 4 GB of VRAM: llama3.2 (2 GB) is the everyday one. Bigger ones still run, split between GPU and CPU, just slower: qwen3.5-abliterated is 17 GB, so most of it runs on the CPU.

FORGE YOUR OWN

Got an old laptop or gaming rig gathering dust? The basic recipe on Ubuntu is short. Check each project's docs for the current install steps.

1. Install the NVIDIA driver

sudo ubuntu-drivers install
sudo reboot
nvidia-smi   # should list the GPU

2. Install Ollama and pull a small model

curl -fsSL https://ollama.com/install.sh | sh
ollama run llama3.2

3. Put Open WebUI in front of it

Open WebUI wants Python 3.11, which newer Ubuntu doesn't ship. uv fetches it and makes a separate environment for it:

curl -LsSf https://astral.sh/uv/install.sh | sh
uv venv --python 3.11 /opt/open-webui/venv
uv pip install --python /opt/open-webui/venv/bin/python open-webui

Then run it as a service, in /etc/systemd/system/open-webui.service:

[Unit]
Description=Open WebUI
After=network-online.target ollama.service
Wants=network-online.target

[Service]
Type=simple
WorkingDirectory=/opt/open-webui
Environment=DATA_DIR=/opt/open-webui/data
Environment=OLLAMA_BASE_URL=http://127.0.0.1:11434
Environment=PORT=8080
ExecStart=/opt/open-webui/venv/bin/open-webui serve
Restart=always

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now open-webui

Updating later: uv pip install --python /opt/open-webui/venv/bin/python -U open-webui, then sudo systemctl restart open-webui.

4. Join it to your Tailscale network

curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up

Then open http://<machine-name>:8080 from any device on your tailnet, or SSH in to manage it. The first account you make is the admin. No ports opened to the internet.

QUESTIONS AT THE BAR
Can I use it?

It's a personal setup on my own private network, not a public service. The recipe above will get you your own.

Is it as good as ChatGPT?

No. Small models running on a laptop GPU can't match the big hosted ones. They're still handy for everyday questions, drafting and tinkering, and they're private.

Why a laptop?

It was already there. Laptops are quiet, sip power and come with a built-in battery backup, which makes them decent little home servers.

What changed from the old laptop?

Local AI started on a retired Lenovo Yoga 730 with no graphics card Ollama could use, so the CPU did everything. The ASUS TUF has an NVIDIA GTX 1650, which Ollama uses automatically once the NVIDIA driver is installed (sudo ubuntu-drivers install, then reboot). ollama ps shows how much of a loaded model sits on the GPU.
